可以。下面给你一套可以直接作为项目 **学生画像 JSON Schema V1.0** 的设计。

这套结构重点解决四件事：

1. 满足赛题“不少于 6 个维度”和“随学随新”的要求。
2. 支持 AI 从对话中增量抽取画像。
3. 支持练习、学习行为等客观数据更新画像。
4. 每一次画像变化都有来源、证据、置信度和更新时间，避免大模型随意覆盖。

---

# 一、整体结构

一张 `student_profile` 表中保存以下字段：

```text
learning_background
learning_goals
ability_profile
common_misconceptions
learning_preference
metacognitive_profile
subject_profiles
```

其中第 7～9 个画像维度统一放在 `subject_profiles` 中：

```json
{
  "DATA_STRUCTURES": {
    "knowledge_mastery": {},
    "learning_behavior": {},
    "current_learning_state": {}
  }
}
```

完整维度关系为：

| 维度     | 存储位置                                                 | 更新频率 |
| ------ | ---------------------------------------------------- | ---- |
| 学习背景   | `learning_background`                                | 低频   |
| 学习目标   | `learning_goals`                                     | 中频   |
| 综合能力   | `ability_profile`                                    | 中频   |
| 易错模式   | `common_misconceptions`                              | 中高频  |
| 学习偏好   | `learning_preference`                                | 中频   |
| 元认知能力  | `metacognitive_profile`                              | 中低频  |
| 知识掌握   | `subject_profiles[subjectId].knowledge_mastery`      | 高频   |
| 学习行为   | `subject_profiles[subjectId].learning_behavior`      | 高频   |
| 当前学习状态 | `subject_profiles[subjectId].current_learning_state` | 实时   |

# 二、所有 JSON 的统一字段规范

## 1. 数值范围

| 字段类型         | 范围       |
| ------------ | -------- |
| 能力分数、掌握度、完整度 | `0～100`  |
| 置信度          | `0～1`    |
| 正确率、完成率、使用率  | `0～1`    |
| 时间           | ISO 8601 |
| 时长           | 统一使用分钟   |
| 趋势           | 枚举值      |

示例时间：

```json
"last_updated_at": "2026-06-15T18:30:00Z"
```

## 2. 统一元数据

每个画像维度都保留一个 `metadata`：

```json
{
  "schema_version": "1.0",
  "confidence": 0.88,
  "completeness": 82.5,
  "source_types": [
    "USER_EXPLICIT",
    "QUIZ_RESULT"
  ],
  "evidence_ids": [
    "msg_10021",
    "answer_8891"
  ],
  "last_updated_at": "2026-06-15T18:30:00Z",
  "updated_by": "PROFILE_AGENT",
  "update_reason": "用户明确说明学习时间，并结合最近练习结果更新",
  "valid_until": null
}
```

字段含义：

| 字段                | 定义               |
| ----------------- | ---------------- |
| `schema_version`  | 当前 JSON 结构版本     |
| `confidence`      | 当前维度整体可信度，0～1    |
| `completeness`    | 当前维度信息完整度，0～100  |
| `source_types`    | 参与生成该维度的数据来源     |
| `evidence_ids`    | 对话、答题、学习事件等证据 ID |
| `last_updated_at` | 最后更新时间           |
| `updated_by`      | 更新者              |
| `update_reason`   | 本次更新原因           |
| `valid_until`     | 画像有效期，稳定画像可为空    |

## 3. 数据来源枚举

```text
USER_EXPLICIT       用户明确表达
USER_CONFIRMATION   用户确认了系统推断
DIALOGUE_INFERENCE  从对话中推断
QUIZ_RESULT         练习或考试结果
CODE_EVALUATION     代码执行或代码评测
LEARNING_BEHAVIOR   学习行为统计
RESOURCE_FEEDBACK   资源评分或反馈
TEACHER_IMPORT      教师导入
SYSTEM_DERIVED      系统计算
```

# 三、维度一：学习背景 `learning_background`

学习背景描述学生较稳定的基础信息。

主要回答：

* 学生是什么专业和年级；
* 学过哪些前置课程；
* 有什么编程和数学基础；
* 每周能投入多少时间；
* 存在哪些学习环境约束。

# 四、维度二：学习目标 `learning_goals`

目标必须是可度量、可跟踪、可完成的，不能只存一句：

```text
我要学好数据结构
```

应该转换成：

* 学什么；
* 学到什么程度；
* 什么时候完成；
* 每周投入多少时间；
* 用什么指标判断完成。

```text
DRAFT
ACTIVE
IN_PROGRESS
PAUSED
COMPLETED
CANCELLED
EXPIRED
```

# 五、维度三：综合能力 `ability_profile`

综合能力不是某个知识点会不会，而是学生跨知识点、跨任务表现出的能力。

对于计算机专业，建议保留以下能力：

1. 概念理解；
2. 抽象建模；
3. 问题拆解；
4. 算法设计；
5. 复杂度分析；
6. 代码实现；
7. 调试分析；
8. 知识迁移；
9. 技术表达。

# 六、维度四：易错模式 `common_misconceptions`

易错模式不只是“做错了哪道题”，而是要识别：

* 错误类型；
* 典型表现；
* 出现频率；
* 可能原因；
* 涉及知识点；
* 应该如何干预；
* 干预后是否改善。

# 七、维度五：学习偏好 `learning_preference`


* 视频经常跳过；

# 十三、AI 实时更新不能直接返回整份画像

AI 每次对话后，不应该重新生成整份 `student_profile`，否则容易：

* 覆盖其他维度；
* 丢失已有字段；
* 把推测当成事实；
* 同一个科目重复插入；
* 出现并发更新冲突。

正确方式是让画像智能体输出“局部更新指令”。

## 推荐更新协议

```json
{
  "expected_profile_version": 12,
  "event_id": "evt_dialogue_10301",
  "event_type": "DIALOGUE",
  "changes": [
    {
      "operation": "UPSERT",
      "dimension": "learning_preference",
      "path": "/subject_overrides/DATA_STRUCTURES/preferred_resource_types",
      "value": [
        "DIAGRAM",
        "CODE_TRACE",
        "CODE_EXAMPLE"
      ],
      "value_source": "USER_EXPLICIT",
      "confidence": 1.0,
      "evidence_ids": [
        "msg_10301"
      ],
      "reason": "用户明确表示学习链表时更喜欢图解和代码执行过程"
    },
    {
      "operation": "UPSERT",
      "dimension": "subject_profiles",
      "path": "/DATA_STRUCTURES/current_learning_state/blocking_issues/ISSUE-001",
      "value": {
        "issue_id": "ISSUE-001",
        "issue_type": "PROCEDURE_ORDER_ERROR",
        "description": "删除节点前没有正确保存引用",
        "severity": "HIGH",
        "status": "ACTIVE"
      },
      "value_source": "MODEL_INFERRED",
      "confidence": 0.93,
      "evidence_ids": [
        "msg_10301",
        "code_eval_205"
      ],
      "reason": "用户描述与代码评测结果一致"
    }
  ]
}
```

推荐操作类型：

```text
SET
UPSERT
REMOVE
APPEND_UNIQUE
INCREMENT
RECALCULATE
```

其中：

* 大模型通常使用 `SET`、`UPSERT`、`APPEND_UNIQUE`；
* 统计服务使用 `INCREMENT`、`RECALCULATE`；
* 删除稳定画像必须谨慎，通常先标记 `INACTIVE`，不要直接删除。

# 十四、不同数据由谁负责更新

这是整个画像系统最重要的规范。

| 数据类型       | 主要更新者        |
| ---------- | ------------ |
| 专业、年级、学习时间 | 用户明确表达       |
| 学习目标       | 用户 + 规划智能体   |
| 声明偏好       | 用户           |
| 实际有效偏好     | 推荐算法和行为统计    |
| 知识掌握度      | 评估服务         |
| 答题正确率      | 后端统计         |
| 学习行为       | 行为分析服务       |
| 易错模式       | 诊断智能体 + 客观证据 |
| 元认知能力      | 评估智能体        |
| 当前困难       | 辅导智能体        |
| 画像摘要       | 大模型生成        |
| 可信度         | 后端计算         |

## 大模型不能直接决定的字段

```text
mastery_score
accuracy_rate
study_minutes
completion_rate
attempt_count
profile_confidence_score
```

这些应该由后端程序根据事实计算。

大模型适合生成：

```text
错误原因假设
学习困难描述
学习策略建议
画像摘要
对话信息抽取
下一步学习建议
```

# 十五、画像冲突处理规则

## 用户声明类字段

例如：

```text
专业
年级
学习目标
可用时间
声明偏好
```

优先级：

```text
用户最新明确表达
> 用户历史表达
> 大模型推断
```

## 掌握度和行为类字段

例如：

```text
知识掌握度
正确率
学习时长
完成率
```

优先级：

```text
客观测试和行为数据
> 教师评价
> 用户自评
> 大模型推断
```

学生说：

> 我已经完全掌握链表了。

不能直接把掌握度设成 100。

应该记录：

```json
{
  "self_reported_level": "MASTERED"
}
```

然后通过练习验证：

```json
{
  "verified_mastery_level": "DEVELOPING"
}
```

# 十六、AI 推断置信度规则

建议使用以下标准：

|         置信度 | 处理方式         |
| ----------: | ------------ |
| `0.85～1.00` | 可自动写入        |
| `0.65～0.84` | 写入为待确认或低可信推断 |
| `0.50～0.64` | 暂存候选，不进入正式画像 |
|     `<0.50` | 不更新          |

用户明确表达：

```text
我每天晚上有一个小时学习。
```

可以设置：

```json
"confidence": 1.0
```

模型根据一句话猜测：

```text
用户可能不喜欢视频。
```

不能直接设置高置信度。

# 十七、9 个维度最终定位

| 维度     | 主要用途               |
| ------ | ------------------ |
| 学习背景   | 判断起点和前置基础          |
| 学习目标   | 制定学习路径和计划          |
| 综合能力   | 决定任务类型和辅导方式        |
| 易错模式   | 生成针对性纠错资源          |
| 学习偏好   | 选择文档、图解、视频、代码等资源形式 |
| 元认知能力  | 决定督学、反思和提醒策略       |
| 知识掌握   | 决定学什么、复习什么         |
| 学习行为   | 判断投入、坚持度和资源效果      |
| 当前学习状态 | 决定此刻智能体应该做什么       |

这套结构已经不仅是为了满足“9 个维度”，而是能够支撑赛题中的：

```text
对话式画像构建
个性化资源生成
动态学习路径规划
精准资源推送
智能答疑
学习效果评估
画像随学随新
```

最适合你当前项目的落地方式是：

> **一张学生当前画像表，7 个 JSON 列；其中 `subject_profiles` 使用科目 ID Map，内部保存知识掌握、学习行为和当前状态。所有更新采用局部 Patch，并为推断结果保存证据 ID、置信度和更新时间。**
